# mactriage v0.2.0 specification

## Goal

Broaden mactriage from a launch-failure specialist into an approachable macOS
application troubleshooting toolkit without weakening its conservative safety
model or its scriptable CLI contracts.

## Interactive home

- Running `mactriage` with no arguments in a terminal opens a colorful inline
  menu instead of Cobra usage text.
- The menu describes tasks in plain language, asks only for inputs needed by
  the selected task, and then runs the same command implementation exposed to
  scripts.
- `mactriage --help`, subcommands, flags, JSON, and redirected execution remain
  conventional and deterministic.
- A no-argument noninteractive invocation prints a short getting-started panel
  rather than the full command tree and exits successfully.

## New commands

### `collect <app>`

Collect a launch diagnosis into an atomic mode-0600 ZIP support bundle. The
archive contains only `report.json`, `summary.txt`, and `manifest.json`; it never
contains raw unified logs, crash reports, or unrelated paths. Interactive runs
preview the file list before writing. `--no-launch` makes collection passive.

### `hang <app|pid>`

Inspect a running application's PID, state, CPU, resident memory, thread count,
and elapsed time. Detect a likely hang or abnormal resource use. A raw Apple
process sample is collected only when `--sample-output` is explicitly supplied,
is written atomically with mode 0600, and is never embedded in JSON reports.

### `permissions <app>`

Inspect declared entitlements and bounded, timestamped `tccd` logs for explicit
privacy denials involving the selected bundle. Report camera, microphone,
screen-recording, Accessibility, Full Disk Access, Automation, Bluetooth,
location, and contacts categories when supported by evidence. Never read or
modify the TCC database. Interactive mode may offer to open Privacy & Security.

### `scan [directory]`

Scan installed applications in standard application directories, or one
explicit directory, with bounded concurrency. Report malformed bundles,
missing or non-runnable executables, invalid signatures, unsupported minimum OS
versions, and Intel-only applications on Apple silicon. Paths are included only
for scanned applications. `--limit` bounds work.

### `compare <before.json> <after.json>`

Compare two schema-compatible mactriage reports and show added, resolved, and
unchanged finding codes plus changed evidence statuses. JSON output is stable
and contains no ANSI sequences.

### `explain <finding-code>`

Explain a stable diagnostic code in plain language, including what it means,
what to do, and what mactriage will not do. Unknown codes fail operationally.

### `summarize <report.json>`

Turn one sanitized report into a concise help-desk/GitHub-ready Markdown
summary. `--json` emits the same summary in a structured envelope.

## Extended `watch`

Every sample additionally reports CPU percentage, resident memory, thread
count, socket count, and cumulative disk bytes when available. Descriptor
behavior and existing NDJSON fields remain backward compatible. Resource
warnings use explicit thresholds configurable by flags.

## Safety and compatibility

- macOS 13+ on arm64 and amd64 remains supported.
- Existing v0.1 commands, flags, report schema version, and exit meanings remain
  compatible; new optional fields are additive.
- Human results use color plus text labels. JSON/NDJSON never contains ANSI or
  progress output.
- All external commands use absolute paths, argument arrays, bounded output,
  locale normalization, and timeouts through the existing command runner.
- Interactive actions default to No. JSON and noninteractive diagnostic modes
  never prompt or mutate.
