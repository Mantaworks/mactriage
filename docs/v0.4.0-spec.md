# mactriage v0.4.0 — The Follow-Through Release

## Objective

Make mactriage substantially easier to adopt for individual Mac users, developers, help desks, and managed fleets without turning it into a cleaner, antivirus, daemon, telemetry agent, or security bypass.

## Product experience

- `mactriage doctor --quick` runs the bounded first-line checks: storage, memory, CPU, descriptors, core services, and network.
- `mactriage doctor --full` runs all checks, including updates, crashes, restarts, startup items, application compatibility, battery, thermal pressure, and Time Machine freshness.
- `--profile quick|full|fleet` provides the same stable automation contract; direct `doctor` remains full-compatible while the guided home uses quick.
- Human output starts with an explicit verdict, shows at most three next-best steps, and labels unavailable measurements as unknown.
- Eligible findings offer only allowlisted actions: open the relevant Storage, Network, Login Items, Battery, Time Machine, Software Update, Privacy & Security, or Activity Monitor surface; every action defaults to No and is verified before the relevant probes rerun.

## Deeper diagnostics

- `mactriage storage` reports startup-disk capacity. `--details` performs an explicitly requested, bounded aggregate scan of standard home categories without exporting individual filenames.
- `mactriage startup` lists sanitized registered background/login items or an explicitly labelled launch-agent fallback and can offer to open Login Items.
- Network evidence additionally distinguishes active-interface availability, self-assigned addressing, Wi-Fi power/association, DNS-server presence, plain-HTTP reachability, and suspected captive interception without exporting SSIDs, IP addresses, DNS addresses, or response bodies.
- Full Doctor collects typed laptop battery facts, thermal limits, and Time Machine destination/backup freshness. Unsupported or unconfigured optional facilities are skipped rather than diagnosed as failures.
- Baseline comparisons expose battery, thermal, backup, and detailed storage changes.

## Automation and privacy

- `mactriage schema [report|watch]` emits bundled JSON Schema.
- Global `--fail-on warning|error|critical`, `--total-timeout`, `--offline`, and `--redact standard|strict` flags have deterministic behavior.
- `--offline` prevents network/update probes; an explicitly requested `network` command rejects it.
- Strict redaction removes user paths and app/process identities while retaining diagnostic codes, severities, aggregate measurements, and report usefulness.
- Every report has a random, non-identifying case ID. Schema compatibility and deprecation policy are documented.
- JSON/NDJSON never contains ANSI or progress output; output files remain atomic and mode `0600`.

## Adoption and trust

- Release archives, checksums, and SBOMs receive GitHub artifact provenance attestations.
- CI verifies reproducible cross-builds, CodeQL, Scorecard, Go/Actions dependency updates, tests, docs, Homebrew generation, and vulnerability scanning.
- README gains a reproducible terminal demo, a 30-second quick start, MDM examples, artifact-verification instructions, and clearer positioning.
- Repository metadata, topics, Discussions, issue forms, pull-request template, code of conduct, roadmap, and contributor starter issues are configured through GitHub CLI/API.
- Homebrew Core readiness is documented and tracked; no upstream submission is made until usage and maintenance maturity support it.

## Safety and non-goals

- Never delete user files, clear caches, remove startup items, alter DNS/VPN/firewall state, toggle Wi-Fi, install updates, change Time Machine, disable Gatekeeper/SIP, rewrite signatures, or silently terminate processes.
- No telemetry, persistent identity, background service, self-update, native GUI, or raw-log upload.
- Warnings do not fail by default. `--fail-on` changes only the requested invocation's exit policy.

## Acceptance

- Unit tests cover profiles, new evidence parsers/rules, exit policy, total timeout, offline behavior, schemas, strict redaction, action allowlisting, comparison metrics, and human/JSON output.
- macOS integration tests exercise passive supported commands while destructive or state-changing actions remain manual.
- Two clean acceptance passes include race tests, vet, shellcheck, vulnerability scan, both architectures, GoReleaser snapshot, SBOMs, provenance configuration, real CLI smoke tests, and Homebrew formula installation.
